# 匠人说 · 非遗生活

手机端交互原型，包含首页、作品识别、AI 非遗问答、体验跟学和个人手账。界面优先适配手机尺寸，也可在桌面浏览器中预览。

## 手机安装与分享

应用已加入 PWA 安装清单、主屏幕图标、原生分享按钮和基础离线缓存。要让其他人打开，需先把整个项目文件夹发布到一个支持 HTTPS 的静态网站托管平台；本地 `index.html` 文件不能直接生成可供他人访问的公共链接。发布后将 HTTPS 链接发给对方即可。安卓 Chrome 通常可从页面菜单选择“安装应用”；iPhone/iPad 请在 Safari 打开链接，点“分享”，再选“添加到主屏幕”。首次联网打开后，页面资源会缓存，之后可离线打开已缓存的界面。

## 本地预览

直接用浏览器打开 `index.html`。也可以在项目目录启动一个静态文件服务：

```bash
npx serve .
```

## 已实现流程

- 首页拍照/选图入口、热门非遗项目卡片、"和传承人聊两句"直达对话入口与底部导航。
- 底部导航含独立「问答」tab，可随时直接进入与 AI 传承人的对话界面。
- 识别页支持三种入口：拍照识别（现场拍照）、从相册选择（上传图库）、音频识别（录音或上传音频）；识别结果卡可继续查看百科、问传承人或进入跟学。
- 音频识别：可调用麦克风实时录音，或从相册/文件上传一段音频，识别声音类非遗（古琴艺术、京剧、皮影戏等，均取自 15 项知识库）。
- 传承人问答：直接回答、口语化术语说明、参考资料折叠、建议追问、五轮对话上限和非遗范围提示。
- 问答覆盖全部 15 项非遗，两种用法并存：默认「随便问」，提问里一旦出现某项目名称或口语别名（漆扇、紫砂壶、糖画、掐丝珐琅、节气……），「正在聊」会自动切到该项目并只用该项目知识库作答；也可以点「换个话题」，从 15 项清单里直接选一项。选中后话题会固定，后续不带项目名的追问（如“它还有谁在做？”）继续沿用当前项目；想解除锁定，选面板最上面的「非遗 · 随便问」，焦点回到自动识别。
- 「换个话题」面板每项都配一张本地的代表性实拍图（`assets/topics/`），当前项打 ✓；没有选中任何项目时「随便问」那一行打 ✓。
- 首页三件套与跟学课程对应国家级名录项目：福州脱胎漆器髹饰技艺（Ⅷ-54）、白族扎染技艺（Ⅷ-26）、东阳竹编（Ⅶ-51）；跟学步骤直接取知识库 `craftSteps`，分步进度、操作易错提醒、mock 三档纠错反馈、断点续学和完成反馈。
- 跟学进度条支持点击任意步骤直接跳转（可回到上一步或跳到后续步骤）。
- 手账时间轴、看过/问过/做过筛选、记录详情与删除、门类/手作/问题统计、徽章和三款分享卡片。
- 手账和跟学进度保存在当前浏览器的 `localStorage` 中。

## Mock 范围

拍照与录音识别已经接了可用的真接口（见下节「识别服务」）：后端在跑且配置了模型 Key 时是真实判断；后端没跑、或只跑在 mock 模式下时，页面会明确标出「演示模式」并给出提示，不会假装识别成功。跟学纠错（`mockStepCheck`）与分享卡片仍是演示数据。问答不再写死在 `renderAnswer` 里：它先在 `heritage-knowledge-15.js` 里认出问的是哪一项，再在该项目的 22–24 条问答中按字符 bigram 重合度、实词命中与意图（做法/历史/传承人/作品/保护/疗效/保养）打分取最贴的一条；问“怎么做”而库里没有流程型问答时，退回跟学步骤或百科【工艺】段；问“有哪些代表作/谁在做”时列出作品与传承人清单。答案与参考资料均来自知识库原文，不做改写。

把问答也换成真模型时，把 `app.js` 中 `detectCraft`、`pickQA`、`renderKBAnswer` 三处的本地检索替换为 `backend` 的 `POST /api/chat` 即可，前端话题、手账、追问建议逻辑无需改动。

## 识别服务（拍照 / 录音）

前端 `app.js` 里的 `IDENTIFY_API` 默认是 `http://127.0.0.1:8000`；换成别的地址（比如内网机器或线上部署域名）时，在浏览器控制台执行 `localStorage.setItem('artisan-api-base','https://你的域名')` 后刷新即可。

启动后端：

```bash
cd backend
pip install -r requirements.txt
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

接口（请求体都是 JSON，图片/音频用 base64，不带 `data:` 前缀）：

| 接口 | 请求体 | 响应关键字段 |
|---|---|---|
| `POST /api/identify` | `{"image_base64":"...","mime":"image/jpeg"}` | `craft_key`、`craft_title`、`certain`、`confidence`、`reason`、`candidates` |
| `POST /api/identify-audio` | `{"audio_base64":"...","mime":"audio/wav"}` | 同上，ASR 路径额外带 `transcript` |
| `GET /` | — | `identify_provider`、`identify_ready`（判断模型是否配好） |

页面上的四种状态，看顶部那行标签就能分辨：

| 情况 | 顶部标签 | 说明 |
|---|---|---|
| 后端在跑 + 配了视觉模型 | 照片识别 · AI 判断 86% | 真识别，下面还有一句「判断依据」 |
| 后端在跑但没配 Key（`IDENTIFY_PROVIDER=mock`） | 照片识别 · 联调模式 | 联调用的固定结果，`reason` 会写明是 mock，不会伪装成 AI 判断 |
| 模型判断证据不足 | 候选列表 | 不硬猜，给 1–2 个最接近的项目让你选 |
| 后端没起或网络失败 | 照片识别 · 演示模式 + toast | 明确告知已退回演示，不是真识别 |

配置写在 `backend/.env`（模板见 `backend/.env.example`），最少四行：

```
IDENTIFY_PROVIDER=llm
IDENTIFY_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
IDENTIFY_API_KEY=你的Key
IDENTIFY_MODEL=你的视觉模型接入点ID
```

换阿里云百炼（通义千问）就是这四行：

```
IDENTIFY_PROVIDER=llm
IDENTIFY_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
IDENTIFY_API_KEY=sk-你的百炼Key
IDENTIFY_MODEL=qwen3.8-flash
```

阿里这条要注意两点：`qwen3.8` 系列默认开思考模式，代码检测到模型名含 `qwen3.5`–`qwen3.8` 会自动传 `enable_thinking=false`（想保留就设 `IDENTIFY_ENABLE_THINKING=1`）；录音那条不能沿用 Qwen-Audio（它不支持 OpenAI 兼容协议），要用 `qwen3.8-omni-flash` 走 `audio_llm`。

### 两个入口怎么分工

| 入口 | 覆盖范围 | 依据 |
|---|---|---|
| 拍照识别 | 全部 15 项 | 看形制、纹样、工艺痕迹 |
| 录音识别 | 只有京剧、皮影戏、古琴艺术 | 听唱腔、念白、锣鼓、丝弦 |

录音的范围是**代码里的硬约束**（`identify.py` 的 `AUDIO_CRAFT_KEYS`），不是只写在提示词里：模型若把一段音频判成景泰蓝、剪纸这类工艺项目，后端会丢掉这个结果，返回 `out_of_scope` 和一句「它没有可辨识的听觉特征，请改用拍照识别」，前端则弹一块「没找到声音类非遗」并给一个「改用拍照识别」的按钮，直接跳到拍照入口。这样不会出现「讲解里提到竹编，结果判成这是一件竹编」的误判。

### 音频要接哪条链路

| 方案 | 配置 | 做法 | 适用 |
|---|---|---|---|
| `AUDIO_PROVIDER=asr`（推荐先用） | `ASR_BASE_URL` / `ASR_API_KEY` / `ASR_MODEL`（whisper 兼容） | 先转写成文字，再把转写内容交给文本模型，从 3 项里选 | 兼容性最好，任何厂商都能用；唱词、念白、讲解都能转写 |
| `AUDIO_PROVIDER=audio_llm` | `AUDIO_BASE_URL` / `AUDIO_API_KEY` / `AUDIO_MODEL` | 音频直接进多模态模型的 `input_audio` 字段，一步判断 | 模型支持音频输入时更准，能听出锣鼓、丝弦、方言腔调 |

两个已知限制，上线前要处理：

1. 浏览器 `MediaRecorder` 录出来是 `audio/webm`。阿里百炼的 omni 模型实测直接接受 webm/opus（见下表），不需要转码；换其他厂商如果拒收，再在服务端用 ffmpeg 转码（`ffmpeg -i in.webm -ar 16000 -ac 1 out.wav`），或前端改用 WebAudio 重采样导出 wav。
2. 白名单是按当前知识库的 15 项定的。以后库里加了民歌、曲艺、地方戏，要把新项目同时写进 `AUDIO_CRAFT_KEYS`，否则录音入口会把它当"非声音类"挡回去。

### 真实模型实测（2026-11-10，阿里百炼）

用 `qwen3.8-flash`（拍照）与 `qwen3.8-omni-flash`（录音）跑了一遍，配置见 `backend/.env`：

| 测试 | 样本 | 结果 |
|---|---|---|
| 15 项代表图 | `assets/topics/` 的 15 张 | 15/15 全部 `certain=true`，置信度 0.95–0.98，单项耗时 1.7–12.7 秒（平均约 4.5 秒） |
| 非非遗图片（页面截图） | 一张 App 界面截图 | 不硬猜，`certain=false`，理由「画面为非遗介绍 APP 界面，非具体工艺实物照片」 |
| 录音（440Hz 正弦，无唱腔） | 1 秒 wav | 链路通，返回「仅听到持续电子蜂鸣声，无唱腔、锣鼓或丝弦等非遗声音线索」，前端弹「改用拍照识别」 |
| 浏览器真实录音格式（webm/opus） | 页面内 MediaRecorder 录的 26KB webm | 直接接受，无需转码，返回「仅有持续电子蜂鸣声」，证明录音入口的 webm 不会被格式挡回 |

逐项明细见 `backend/identify-regression-15.json`。两点局限要说清：一是这 15 张是各项目的代表图，属于"标准样本"，命中率不能等同于随手拍的命中率；二是录音只验证了链路与"无声音线索"分支，还没有用真实唱腔/锣鼓样本验证过正例。

百炼这条音频链路有一个必须的格式细节：`input_audio.data` 要按 data-URI 传（`data:audio/wav;base64,...`），纯 base64 会报 `The provided URL does not appear to be valid`。代码对模型名含 `omni` 的自动加前缀，其他厂商可设 `AUDIO_DATA_URI=1` 打开。


注：首页早前展示的“漆扇”是水上漂漆的文创体验产品，并非国家级非遗名录项目；名录中对应的是**福州脱胎漆器髹饰技艺**（2006 年第一批，项目编号 Ⅷ-54）。页面现已统一改为知识库中的正式项目名称，旧手账里以“漆扇”记录的条目会自动迁移到该项目下。

## 非遗知识库

- `heritage-knowledge-15-v2.json`：15 项国家级非遗的深度版主数据，含每项 22–24 条问答（共 343 条）、五段式百科（653–939 字）、代表作品、传承谱系与来源清单。
- `heritage-knowledge-15.js`：由上述 JSON 生成的前端版本（`window.HERITAGE_KB_15`），含名称、口语别名、问答、跟学步骤、代表作、传承人、百科与来源，问答页的话题识别与本地检索都读它。重新生成需改数据后重跑生成脚本，不要手工编辑。
- `assets/topics/`：15 项非遗各一张代表性图片，用于话题面板图标、手账缩略图与百科弹窗配图。图片取自公开检索结果，仅作项目演示用，不作商业发布；如需正式上线请替换为有授权的素材。
- `非遗知识库15项深度版说明.md`：逐项说明问答数量、代表作品、传承人、来源与可信度标注。
- `heritage-chunks-v1.json`：供问答检索使用的 614 个切块单元。
- `backend/`：RAG 问答后端（检索 + Prompt + 大模型直连），详见 `backend/README.md`。
